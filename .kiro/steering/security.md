# Security and tenant isolation

## Tenant isolation (defence in depth)
1. **Database:** every tenant table has `organization_id NOT NULL`, indexed, with RLS enabled and the policy `organization_id = NULLIF(current_setting('app.current_org', true), '')::uuid`. `NULLIF` is needed because a pooled connection resets the setting to `''` after a transaction, and casting `''` to uuid fails. The application connects as `veritas_app`, which is not the table owner and has no `BYPASSRLS`, so the policies always apply to it. RLS is `ENABLE`d but deliberately not `FORCE`d: the few pre-authentication lookups (memberships of a user, refresh token by hash) run through `SECURITY DEFINER` functions owned by the owner role. Those functions return minimal columns and are executable only by `veritas_app`. Each request transaction runs `set_config('app.current_org', :org, true)` (the bound-parameter form of `SET LOCAL`).
2. **Services:** queries also filter by `organization_id` explicitly. RLS is the backstop, not the only check.
3. **API:** a resource in another organization returns **404**, never 403, so ids cannot be probed.
4. **Storage:** keys are prefixed with the organization id and generated by the server. Downloads go through short-lived signed URLs (60 seconds), and every access is logged.
5. **Graph and vector stores (later phases):** every node and point carries `organization_id`, and every query filters on it.

## Authentication
- Passwords are hashed with Argon2id (argon2-cffi defaults or stronger). Minimum password length is 12.
- Access tokens are JWTs (HS256) valid for 15 minutes, with claims `sub`, `org`, `role`, `type=access`, `jti`, `exp`, `iat`.
- Refresh tokens are opaque random strings, stored as SHA-256 hashes, and rotated on every use. Reuse of a rotated token revokes the whole token family.
- Login is rate-limited per IP and email (Redis). Failures return a generic message.
- Logout revokes the refresh-token family.

## Authorization
- Roles: `org_admin`, `investigation_manager`, `investigator`, `reviewer`, `read_only_analyst`.
- Permissions live in one map in `app.core.permissions`. Endpoints declare `Depends(require_permission("..."))`. Never check role names inline.

## Input and output
- Validate everything at the API boundary with Pydantic. Paginated limits are capped at 100.
- Queries are parameterized through the SQLAlchemy ORM or `text()` with bound parameters. Never build SQL with f-strings.
- Error responses use problem+json with no stack traces or internal ids.
- Never log tokens, passwords, secrets or document text.
- Secrets come only from the environment. `.env` is git-ignored.

## Audit
Write `audit_logs` rows for login success and failure, logout, registration, organization changes, membership and role changes, document access and downloads, and finding status changes.
